# B0 — The `count` trap

What does `terraform plan` show when a middle landlord account is removed from the list? Why is
that dangerous here? What's the fix?

# B0 — The `count` trap

When Terraform uses `count` to create resources from a list, it identifies each resource using its position in that list.

For example, assume the landlord accounts are:

```hcl
landlord_accounts = [
  "la-001",
  "la-002",
  "la-003",
  "la-004"
]
```

Terraform creates four S3 buckets with indexes from `0` to `3`.

If we remove the middle account, `la-002`, the list becomes:

```hcl
landlord_accounts = [
  "la-001",
  "la-003",
  "la-004"
]
```

The problem is that Terraform still identifies resources by their indexes. After removing `la-002`, `la-003` moves from index `2` to index `1`, and `la-004` moves from index `3` to index `2`.

When I run `terraform plan -refresh=false`, Terraform detects that the resource values no longer match the resources associated with those indexes. It can plan to destroy and recreate buckets instead of simply removing the bucket belonging to `la-002`.

This is dangerous because each bucket contains landlord-specific data, such as property images and other media. An unnecessary destroy-and-recreate operation could cause data loss, service disruption, or resources being associated with the wrong landlord account.

**The fix is to use `for_each` instead of `count`.**

With `for_each`, Terraform identifies each resource using the landlord account ID itself rather than its list position.

For example:

```hcl
resource "aws_s3_bucket" "landlord_media" {
  for_each = toset(var.landlord_accounts)

  bucket = "haven-media-${each.key}"
}
```

Now, each bucket has a stable identity, such as `aws_s3_bucket.landlord_media["la-003"]`. If `la-002` is removed, Terraform can identify that specific account's bucket for removal without shifting the identities of the other buckets.

**Conclusion:** Using `count` is risky when resources are associated with specific landlord accounts because removing an item from the middle of a list can change resource indexes. Using `for_each` provides stable resource identities and makes the infrastructure safer to manage as landlord accounts are added or removed.
